# Duct Adapter Generator — handoff spec

**For:** the Application Engineering Toolbox prototype (Claude Design).
**From:** the working generator in `Salsa3DPrinting/Salsa3D` (`cad/adapter.py`, `cad/fanlib.py`, `cad/adapter_app/`),
generator version 1.0.

This folder holds everything needed to add the tool to the toolbox:

| File | What it is |
|---|---|
| `README.md` | This spec: what the tool does, the screens, every rule and formula, the API, acceptance tests. |
| `adapter-data.json` | All data the tool uses: fitting tables (with sources), constants, option defaults and limits, the fitting catalog for dropdowns, fan form fields, built-in fans. Generated from the code. |
| `test-vectors.json` | 8 worked cases: inputs and expected outputs (lengths, diameters, warnings, half-section profiles). A port is right when it reproduces these. |
| `api-examples.json` | Real request/response bodies from the working app. |

The JSON files are generated by `python -m cad.adapter_export`. If the generator changes, regenerate them; don't
hand-edit.

---

## 1. What the tool does

An application engineer picks a **fan** and a **pipe fitting**, and the tool generates a 3D-printable duct adapter
that bolts to the fan on one end and connects to the fitting on the other, with a tapered transition between them.

Output: a print-ready 3MF and STL (mm, Z up, flange flat on the bed, no supports needed), a section drawing, a
small **fit-test print** of just the fitting end, and a report with the key dimensions and any warnings.

Supported fittings (sizes in inches, nominal):

| Fitting | Sizes | Meaning |
|---|---|---|
| PVC Sch 40 **spigot** | 1/2, 3/4, 1, 1-1/4, 1-1/2, 2, 2-1/2, 3, 4, 6, 8, 10, 12 | Adapter end goes **into** a PVC fitting's socket (acts like a piece of pipe). |
| PVC Sch 40 **socket** | same | Adapter end slips **over** a PVC pipe; the pipe stops on an inner ledge. |
| NPT **male** | 1/8, 1/4, 3/8, 1/2, 3/4, 1, 1-1/4, 1-1/2, 2, 2-1/2, 3, 4 | Tapered pipe thread on the outside. |
| NPT **female** | same | Tapered pipe thread on the inside. |
| **Tri-clamp** ferrule | 1-1/2, 2, 2-1/2, 3, 4, 6 | Sanitary clamp flange with gasket groove. |

Fans are square-frame fans with 4 mounting holes at the corners. Users add their own fans through a form.

## 2. What the prototype can do on its own, and what needs the geometry engine

The geometry engine (solid modeling, threads, STL/3MF export) is **Python** (trimesh + manifold3d). A Claude Design
prototype runs in the browser and can't run it. But most of the tool is plain arithmetic, so it ports to JavaScript
exactly:

| Part | In the browser prototype? | How |
|---|---|---|
| Fitting dropdowns, sizes, labels | Yes | `adapter-data.json` → `fittings`. |
| Fan list, fan form, validation | Yes | `builtin_fans`, `fan_fields`, rules in §6. Same error messages. |
| Every number in the report (lengths, diameters, transition, bed fit, warnings) | Yes | Formulas in §4–§5. Check against `test-vectors.json`. |
| Section drawing | Yes | Draw the `outer_profile` / `inner_profile` polylines mirrored about the axis (SVG). |
| 3D preview | Approximate | Revolve the profile (e.g. three.js `LatheGeometry`) and add the square flange plate. Threads and the tri-clamp groove won't show; label it "preview". |
| STL / 3MF / fit-test files | **No** | Needs the engine. In the prototype, show the download list as it will appear, disabled, with "Generated by the adapter engine". |

**For production**, the toolbox would call the engine as a service with the API in §7. The existing local app
already implements that API (Python standard library HTTP server), so it can be hosted as-is behind the toolbox.
Porting the solid modeling to JavaScript (e.g. manifold-3d's WebAssembly build) is possible but is a full
rewrite, with the threads as the hardest part. Decide that later; the UI and data contract don't change either way.

## 3. Screens and flows

The existing app has three tabs. In the toolbox it can be one tool page with these sections.

### 3.1 Make adapter

**Inputs**

1. **Fan side**: dropdown of fans, sorted by name. Unverified fans show "(unverified)" after the name. The last
   option is "— a fitting instead of a fan —", which reveals a second fitting picker so two fittings can be adapted
   to each other.
   Under the dropdown, a one-line summary of the selected fan:
   `120 mm frame, 12 mm holes on a 138.0 mm bolt circle, 100 mm opening. <notes>`
2. **Fitting side**: fitting picker:
   - **Type** dropdown (labels from `fittings[*].label`).
   - **Size** dropdown, filled from the chosen type's `sizes` (shown as `4 in`, `1-1/2 in`).
   - **"…or type it"** text box: free text that overrides the dropdowns (grammar in §4.1). Placeholder:
     `e.g. 4in sch40 pvc spigot, 2" fnpt, 1.5 tri-clamp`.
3. **Advanced** (collapsed): five numeric fields with defaults from `options.defaults`:

   | Field | Key | Default | Limits |
   |---|---|---|---|
   | Taper half-angle (deg) | `taper_deg` | 15 | > 0 and ≤ 45 |
   | Wall thickness (mm) | `wall` | 3.5 | 1.2 – 10 |
   | Spigot OD vs pipe OD (mm) | `spigot_allowance` | −0.3 | −2 – +1 |
   | Socket ID vs pipe OD (mm) | `socket_clearance` | 0.5 | 0 – 3 |
   | NPT clearance per side (mm) | `npt_clearance` | 0.1 | 0 – 0.5 |

   Help text: "Smaller taper = gentler cone but a longer part. Tune the fit values after printing a fit-test piece;
   they only change the fitting end."
4. **Generate** button.

**States**

- *Working*: spinner, "Building the model… threaded ends take up to about 15 seconds." (Real timings: PVC and
  tri-clamp under 1 s; NPT 2–4 s on a laptop.)
- *Error*: red text under the button with the engine's message, e.g.
  `'pvc-5-sch40-spigot': no PVC data for 5 in; known sizes: 1/2, 3/4, …`
- *Result*:
  - Title: `<bottom label> to <top label>`, e.g. "BFS-i06 120 x 75 mm fan to 4 in Sch 40 PVC spigot".
  - Warnings as amber boxes (exact texts in §5.3).
  - 3D view (drag to rotate, scroll to zoom) next to the section drawing.
  - Summary table: overall length (mm and in); size X × Y × Z; fits on each printer (yes/NO); transition
    "ID 100 → 107 mm over 30 mm"; one row per end with its dimensions (§4.2 field names → labels in §8); bolt
    access "clear" or "BLOCKED, see warning".
  - Downloads: adapter STL, adapter 3MF ("open in Bambu Studio"), preview image, section image, fit-test
    print(s), report.json.
  - Footer: "Print the fit-test piece first and try it on the real fitting."

### 3.2 Fans

- **Table** of fans: name (with "added by, date" underneath), frame, bolt circle Ø, holes (`4 × Ø12`), opening Ø,
  status badge (verified / unverified), and Edit / Delete for user fans ("built-in" for built-ins, which can't be
  edited or deleted). Hovering a row shows its notes.
- **Add a fan** opens the form:
  - Name (required). When editing, the name is read-only (it's the id).
  - The eight numeric fields from `fan_fields`, each with its label, "(mm)" and help text.
  - **Hole pattern given as**: radio, "Bolt circle diameter" (default) or "Square spacing (center to center)".
    Spacing hides the bolt-circle field and shows "Hole spacing (mm)"; it's converted with
    `bolt_circle_d = spacing × √2`.
  - Added by, Notes / source (placeholder "Drawing number, datasheet link, what was measured vs assumed").
  - Checkbox "Dimensions checked against the drawing or the real fan" → `verified`.
  - Save / Cancel. Validation errors are listed under the buttons (§6).
  - **Diagram** next to the form: square frame with rounded corners, the air opening circle, a dashed hub-plate
    circle, the dotted bolt circle through the four corner holes, a dashed diagonal through two holes, and labeled
    leaders: Frame size, Square spacing, Bolt circle Ø, Hole Ø, Air opening Ø, Hub plate Ø, Corner radius.
    Caption: "Holes are at the four corners (45°). Dimensions in mm. The hub plate is the motor plate that sticks
    out past one face; use 0 if it's flush."
- Delete asks for confirmation: "Delete <name> from the library? Everyone using this library will lose it."

### 3.3 Settings (desktop app only)

The desktop app stores the fan library in a JSON file that can be on a shared drive, plus an output folder. In
the toolbox, replace this with the toolbox's own storage (a shared fans table) and drop the folder settings.

### 3.4 Safety notes to show somewhere visible

- Print the fit-test piece first and try it on the real fitting.
- PLA softens around 55–60 °C. Use PETG or ASA for warm air, sun, or a hot vehicle.
- Printed NPT threads are for low-pressure air with tape or sealant, not for pressure.
- Mark a fan "verified" only after checking it against the drawing or the real fan.

## 4. Data model

### 4.1 Fitting spec strings

Each end of an adapter is a short text spec. The dropdowns produce canonical specs (`fittings[*].sizes[*].spec`);
the free-text box accepts looser forms. Matching is case-insensitive, `"` means inches.

| Kind | Canonical | Also accepted |
|---|---|---|
| Fan | `bfs-i06` (the fan's id) | `fan-bfs-i06` |
| PVC | `pvc-4-sch40-spigot`, `pvc-1-1/2-sch40-socket` | `4in sch40 pvc spigot`, `1.5 in schedule 40 pvc socket`, `1 1/2 sch 40 pvc spigot` |
| Tri-clamp | `triclamp-1-1/2` | `triclamp-1.5`, `1.5in tri-clamp`, `tc 1.5`, `1-1/2 tri clamp`, `sanitary 2` |
| NPT | `npt-2-male`, `npt-2-female` | `2in fnpt`, `mnpt 2`, `2" npt female` |

Sizes: whole numbers, decimals, fractions or mixed (`1-1/2`, `1 1/2`, `1.5`, `3/4`). Rules and messages:

- PVC needs a schedule and `spigot`/`socket`, or: `'<spec>': PVC spec needs a schedule and spigot/socket, e.g. 'pvc-4-sch40-spigot'`.
- Only Schedule 40: `'<spec>': only Schedule 40 socket depths are in the table so far`.
- NPT needs male/female: `'<spec>': say male or female, e.g. 'npt-2-male' (male = threads on the outside)`.
- Unknown size: `'<spec>': no <PVC|NPT|tri-clamp> data for <size> in; known sizes: <list>`.
- Anything else: `Unknown fitting '<spec>'. Fans: <ids>; PVC like 'pvc-4-sch40-spigot'; 'triclamp-1.5'; 'npt-2-male'.`
- Fan-to-fan is not supported: `Fan-to-fan adapters are not supported yet`.

Labels shown to users: `4 in Sch 40 PVC spigot`, `1-1/2 in tri-clamp ferrule`, `2 in NPT male`, and the fan's name.

### 4.2 Fan

```json
{
  "id": "bfs-i06", "name": "BFS-i06 120 x 75 mm fan",
  "frame": 120.0, "corner_r": 15.0, "depth": 75.0,
  "bolt_circle_d": 138.0, "hole_d": 12.0, "bore_d": 100.0,
  "hub_d": 70.0, "hub_proud": 7.9,
  "verified": true, "added_by": "built-in", "notes": "…", "added_on": "", "builtin": true
}
```

- `id` = name lowercased, runs of non-alphanumerics → `-`, trimmed (`"ACME 80 x 25"` → `acme-80-x-25`).
- Holes are always 4, at 45°, 135°, 225°, 315° on the bolt circle.
- `depth` is for reference only; it doesn't affect the geometry.
- `hub_d` / `hub_proud`: the motor hub plate that sticks out of one face (0 if flush).
- API responses also include `hole_spacing = bolt_circle_d / √2`.

### 4.3 Options

See the Advanced table in §3.1. `options` in a request may omit any key; blanks mean the default.

## 5. Geometry rules

Units are mm. Z is the airflow axis. Each end is described by a **half-section profile**: (r, s) points, with
radius r from the axis and distance s from that end's face (s = 0 at the face, increasing toward the transition).

### 5.1 Ends

`IN = 25.4`. `wall`, `spigot_allowance` etc. are the options.

**Fan flange** (always the bottom end, face on the bed)
- r = bore_d / 2; length = 10 (flange thickness).
- outer: (r + wall, 0), (r + wall, 10). inner: (r, 0), (r, 10).
- Plus a flat plate, 10 thick: square of side `frame` with corner radius `corner_r`, minus 4 holes of `hole_d`
  at 45° on the bolt circle.
- info: `fan_id, bore_d, flange_t, frame, bolt_circle_d, hole_d, holes`.

**PVC spigot**
- pipe_od = `pipe_od_in[size]` × IN; depth = `pvc_sch40_socket_depth_in[size]` × IN.
- od = pipe_od + spigot_allowance; ro = od / 2; ri = ro − wall; length = depth + 6.35 (spigot is 1/4 in longer than
  the fitting's socket, so the fitting never reaches the neck).
- outer: (ro − 1, 0), (ro, 1), (ro, length) (1 mm lead-in chamfer at the tip). inner: (ri, 0), (ri, length).
- info: `pipe_od, spigot_od, spigot_id, spigot_length, fitting_socket_depth`.

**PVC socket**
- ri_sock = (pipe_od + socket_clearance) / 2; ri_join = pipe_od / 2 − 4 (the 4 mm ledge the pipe stops on);
  ro = ri_sock + wall; length = depth + wall.
- outer: (ro, 0), (ro, length). inner: (ri_sock, 0), (ri_sock, depth), (ri_join, depth), (ri_join, length).
- info: `pipe_od, socket_id, socket_depth, stop_ledge_id`.

**Tri-clamp ferrule**
- From `triclamp[size]`: rf = flange_od_in × IN / 2; rt = tube_od_in × IN / 2;
  ri = min(tube_id_in × IN / 2, rt − 2.0).
- Profile constants (`constants.triclamp_profile`): rim_t = 2.84, bevel = 20°, groove w = 3.8, depth = 1.59.
- s_bevel = rim_t + (rf − rt) × tan(20°); length = s_bevel + 10 (plain tube behind the bevel for the clamp jaws).
- outer: (rf, 0), (rf, rim_t), (rt, s_bevel), (rt, length). inner: (ri, 0), (ri, length).
- Gasket groove cut into the face, centered on the bead circle (gasket_bead_d_in × IN / 2): a circular segment
  3.8 wide and 1.59 deep (circle radius rg = (w²/4 + d²) / (2d), center at s = d − rg).
- info: `flange_od, tube_od, bore, gasket_bead_d, groove_w, groove_depth, bevel_deg`.

**NPT** (ASME B1.20.1)
- From `npt[size]` and `pipe_od_in[size]` (= D): p = 1 / tpi (in); E0 = D − (0.05 D + 1.1) p; E1 = E0 + L1 / 16;
  L2 = (0.8 D + 6.8) p. In mm, p_mm = p × IN.
- Thread form: 60°, right-hand, taper 1:16 on diameter, sharp-V height H = p_mm × √3 / 2, truncated top and bottom
  by (H − 0.8 p_mm) / 2 so the thread height is 0.8 p_mm.
- Thread length t_len = L2 × IN + 2 p_mm; length = t_len + 6 (plain collar).
- **Male** (s = 0 is the small end, the tip): pitch radius r_p(s) = (E0 × IN + s / 16) / 2 − npt_clearance;
  root(s) = r_p − H/2 + trunc; major(s) = r_p + H/2 − trunc.
  Bore ri = root(0) − min(3, max(1.2, 0.3 × root(0))).
  Profile (the thread itself is added as a separate solid): outer (root(0) − 0.3, 0), (root(t_len) − 0.3, t_len),
  (major(t_len), t_len), (major(t_len), length); inner (ri, 0), (ri, length). The first thread is chamfered
  (radius ≤ root(0) + 0.5 + s).
  info: `tpi, major_d_at_tip, major_d_at_thread_end, thread_length, bore, radial_clearance`.
- **Female** (s = 0 is the mouth): r_p(s) = (E1 × IN − s / 16) / 2 + npt_clearance; minor/major as above.
  ro = major(0) + max(wall, 5); ri = minor(t_len) − 0.5.
  Profile (the thread is cut separately): outer (ro, 0), (ro, length); inner (ri, 0), (ri, length). Mouth
  chamfer: radius ≥ major(0) + 0.5 − s.
  info: `tpi, major_d_at_mouth, tapped_depth, outer_d, bore_below_thread, radial_clearance`.
- Warning when tpi ≥ 18 (1/8, 1/4, 3/8): see §5.3.

For drawing the section in the prototype, the threaded zone of the profile is a smooth stand-in. Draw it as a
sawtooth between root and major (male) or minor and major (female) over `thread_length` / `tapped_depth` if you
want it to look like a thread.

### 5.2 Assembling the adapter (layout)

1. If the second end is the fan, swap so the fan is the bottom end (a). Fan-to-fan is an error.
2. ra, rb = inner radius where each end meets the transition (the last inner point of each end);
   oa, ob = outer radius there (last outer point).
3. taper_len = max(|rb − ra|, |ob − oa|) / tan(taper_deg).
4. If a is a fan, keep the bolt heads reachable:
   keepout_r = bolt_circle_d / 2 − hole_d (keep-out circle 2 × hole_d around each bolt).
   - If max(oa, ob) > keepout_r: add a **straight neck** of 30 mm at the fan's radius before the taper.
   - Else: taper_len = max(taper_len, 30).
5. z_t0 = a.length; z_t1 = z_t0 + straight + taper_len; top = z_t1 + b.length (= overall length).
6. Whole profile from the bed up: a's points; then (oa or ra, z_t0 + straight); then b's points flipped:
   each (r, s) becomes (r, top − s), in reverse order. Same for inner. Between the listed points everything is a
   straight line (the taper is a cone).

Rotate the profile about Z to get the body; add the fan plate; cut the bore; add/cut threads and the groove.

### 5.3 Checks and warnings (exact texts)

| Check | Condition | Warning |
|---|---|---|
| Unverified fan | fan.verified is false | `Fan '<name>' is not marked verified; check its dimensions.` |
| Fine NPT | tpi ≥ 18 | `<label>: <tpi> threads per inch (<p_mm> mm pitch) is fine for FDM; expect a rough thread and use sealant. A 0.2 mm nozzle helps.` |
| Bolt access | max outer r between z = 10 and z = 40 > keepout_r, or (spigot) top − socket depth < 40 | `Bolt heads may be hard to reach: the adapter reaches <r> mm from the center within 30 mm of the flange, but the bolt heads need it inside <keepout_r> mm.` |
| Frame overhang | oa > frame / 2 | `The duct wall (Ø<2·oa>) is wider than the <frame> mm frame, so it overhangs the frame's flat sides slightly. It prints fine; check nothing next to the fan is in the way.` |
| Hub clearance | inner r at z = min(hub_proud + 1, 10) < hub_d / 2 + 1 | `The fan's hub plate (Ø<hub_d>) may touch the adapter: the bore at the flange is Ø<d>, which leaves less than 1 mm around it.` |
| Bed fit | for each printer: sorted XY extents ≤ sorted printer XY, and Z ≤ printer Z | none per printer; if neither fits: `Too big for both printers' build volumes.` |

Extents for the bed check: X = Y = max(frame (if fan), 2 × largest outer radius), Z = overall length.
Printers: Bambu Lab P1S 256 × 256 × 256, Bambu Lab H2D 350 × 320 × 325.

### 5.4 Fit-test pieces

- Spigot: three rings, 12 mm tall, wall `wall`, OD = pipe_od + spigot_allowance + (0.2, 0, −0.2), named
  `fit-ring-od<OD with 2 decimals>.stl`.
- NPT and tri-clamp: the fitting end alone (with its collar or neck), face up, `fit-test-<label slug>.stl`.
- PVC socket: none.

## 6. Fan form validation (exact messages)

Steps 1 and 2 are checked together and all their errors shown at once; step 3 runs only if they pass.

1. `Name is required.`; if a spacing was given and isn't a number: `Hole spacing must be a number.`
2. Each numeric field: missing → `<Label> is required.` (except corner radius, hub plate diameter and height,
   which default to 0); not a number → `<Label> must be a number.`; outside its min/max → `<Label> must be between
   <min> and <max> mm.` (ranges in `fan_fields`).
3. Geometry (with half = frame/2, hole_xy = bolt_circle_d / 2 / √2, adapter wall 3.5):
   - corner_r > half → `Corner radius can't be more than half the frame size.`
   - bore_d ≥ frame → `Air opening must be smaller than the frame.`
   - hole_xy + hole_d/2 > half − 1 → `Holes fall outside the frame: hole centers at ±<hole_xy> mm, frame edge at ±<half> mm.`
   - bolt_circle_d/2 − hole_d/2 < bore_d/2 + 3.5 → `Holes are too close to the air opening to leave room for the adapter wall.`
   - hub_d > 0 and hub_d ≥ bore_d → `Hub plate must be smaller than the air opening (or the adapter would sit on it).`
4. id empty after slugging → `Name must contain letters or numbers.`

Saving: a built-in id → `'<id>' is a built-in fan; pick another name.`; an existing id without overwrite →
`A fan named '<id>' already exists in the library.`

## 7. API contract

The existing app serves this on `http://127.0.0.1:<port>`. JSON in and out; errors are HTTP 400 with
`{"error": "..."}` (or `{"errors": [...]}` from the fan form), unexpected failures HTTP 500. Full bodies are in
`api-examples.json`.

| Method & path | Body | Returns |
|---|---|---|
| `GET /api/catalog` | — | `{fans: [Fan…], fan_error, fan_fields, fittings, defaults, settings, version}` |
| `POST /api/generate` | `{a: spec, b: spec, options?: {…}}` | Report (below). Both specs are parsed first, so a typo fails fast. |
| `GET /api/jobs/<job>/<file>` | — | The file. Add `?download=1` for `Content-Disposition: attachment`. |
| `POST /api/fans` | `{fan: {…form fields…}, overwrite: bool}` | `{ok, fan}` or 400 `{errors: [...]}` |
| `POST /api/fans/delete` | `{id}` | `{ok}` |
| `POST /api/settings` | `{fan_library, output_dir}` | `{ok, settings}` (desktop only) |
| `POST /api/open-folder` | `{job}` | Opens Explorer (desktop only) |
| `POST /api/quit` | — | Stops the app (desktop only) |

**Report** (response of `/api/generate`):

```
generator_version, options{taper_deg, wall, spigot_allowance, socket_clearance, npt_clearance},
title, stem, job, folder,
fittings: {"bottom (on bed)": {name, …info}, "top": {name, …info}},
overall_length_mm, overall_length_in,
transition: {from_id, to_id, straight_neck, taper_length, z: [z0, z1], wall_at_ends: [a, b]},
extents_mm: [x, y, z], watertight, bodies, volume_cm3,
warnings: [string],
bolt_access: {keepout_r, max_outer_r_in_zone, zone_height, ok, pvc_fitting_mouth_z?},   (fan adapters only)
hub_clearance: {hub_d_assumed, bore_d_at_face, ok},                                     (fan adapters only)
fits_bed: {"Bambu Lab P1S": bool, "Bambu Lab H2D": bool},
files: [file names]   (STL, 3MF, preview PNG, section PNG, fit-test STLs; report.json is also served)
```

Security rules the service follows (keep them if it's hosted): bind to localhost or sit behind the toolbox's auth;
reject requests whose `Host`/`Origin` isn't the app's own; serve job files only from that job's folder; 64 KB
request limit; specs are parsed, never executed.

## 9. Acceptance tests

A port (JavaScript numbers in the prototype, or a new engine) is correct when, for every case in
`test-vectors.json`, it reproduces `overall_length_mm`, `transition`, `bottom_info`, `top_info`, `warnings` and the
profiles to within 0.01 mm. Spot checks:

| Case | Overall length | Transition ID | Notes |
|---|---|---|---|
| bfs-i06 → pvc-4-sch40-spigot | 97.15 | 100 → 107.0 over 30 (bolt-access minimum) | spigot OD 114.0 |
| bfs-i06 → pvc-6-sch40-spigot | 236.33 | 100 → 160.97, 30 straight + 113.78 taper | flare needs the straight neck |
| bfs-i06 → triclamp-1-1/2 | 153.65 | 100 → 34.1 over 128.57 | at taper 37°: 70.79 (the user's hand-made adapter is 69.2) |
| bfs-i06 → npt-2-male | 133.56 | 100 → 49.67 over 93.92 | thread OD at tip 59.20 |

Engine-only checks (already covered by the repo's tests): every catalog size builds as one closed, watertight
body; threads are right-handed with a 1:16 taper; bolt holes sit at ±48.79 mm for the BFS-i06.

## 10. What's verified, what's assumed, and limits

- **Verified against sources:** PVC pipe ODs and Sch 40 socket depths; NPT dimensions (formulas reproduce the
  standard's tables); tri-clamp flange ODs, tube sizes and gasket bead diameters.
